1. Traffic နှင့် Workload ကို ဦးစွာ တွက်ချက်ခြင်း (Capacity Planning)

စနစ်တစ်ခု မတည်ဆောက်မီ သုံးစွဲသူ အရေအတွက်ပေါ် မူတည်၍ Server ပေါ်သို့ ကျရောက်လာမည့် ဝန်ထုပ်ဝန်ပိုး (Workload) ကို ကြိုတင် တွက်ချက်ရပါမည်။ ဥပမာအားဖြင့် စုစုပေါင်း သုံးစွဲသူ ၁၀၀,၀၀০ (100k Users) ရှိသော စနစ်တစ်ခုအတွက်:

DAU (Daily Active Users)

ပုံမှန်အားဖြင့် Total Users ၏ ၁၀% မှ ၂၀% ခန့် (၁၀,၀၀၀ မှ ၂၀,၀၀၀ ဦး) သည် တစ်နေ့တာအတွင်း ဝင်ရောက် အသုံးပြုကြပါသည်။

Concurrent Users

Peak Hours (အလုပ်အများဆုံး အချိန်) တွင် တစ်ပြိုင်နက်တည်း ဝင်ရောက်နေသူ ၁,၀၀၀ မှ ၂,၀၀၀ ဦးအထိ ရှိနိုင်ပါသည်။

RPS (Requests Per Second)

User တစ်ဦးလျှင် 1 Request နှုန်းဖြင့် Peak Time တွင် Server သည် 1k - 2k RPS ကို လက်ခံပေးနိုင်ရန် လိုအပ်ပါသည်။

2. Array ရှာဖွေခြင်း O(n) နှင့် Hash Map O(1) Production နှိုင်းယှဉ်ချက်

Production တွင် Data များပြားလာသည်နှင့်အမျှ Data Structure ရွေးချယ်မှုသည် Server ၏ CPU Load ကို တိုက်ရိုက် သက်ရောက်စေပါသည်။

Array ရှာဖွေခြင်း (Linear Search)

O(n) - နှေးကွေးသည်

Data (၁ သန်း) ရှိသော Array ထဲမှ User တစ်ဦးကို ရှာသည့်အခါ `.find()` သို့မဟုတ် Loop ဖြင့် အစမှအဆုံး တစ်ခုချင်းစီ လိုက်စစ်ရသဖြင့် Data များလေလေ အချိန်ကြာလေလေ ဖြစ်ပါသည်။ 

// Data 10,000 ခုရှိလျှင် 10,000 ခา လိုက်စစ်ရသည်
const user = usersArray.find(u => u.id === "u999"); // O(n)

Hash Map ရှာဖွေခြင်း (Key-Value)

O(1) - အလွန်မြန်သည်

Production တွင် Array အစား Object သို့မဟုတ် Redis (In-memory Cache) ကို အသုံးပြု၍ Key ဖြင့် တိုက်ရိုက်ခေါ်ယူပါက Data ဘယ်လောက်များပါစေ ချက်ချင်း ရရှိနိုင်ပါသည်။ 

// Key ဖြင့် Memory နေရာသို့ တိုက်ရိုက်သွားယူသည်
const user = usersMap["u999"]; // O(1) (Instant)
