UI/UX Design Pipeline & Dev Handover Master Guide[cite: 2]

၁။ အဓိက လုပ်ငန်းစဉ် အကျဉ်းချုပ် (Executive Summary & Core Pipeline)[cite: 2]

User Requirements → User Flow → Lo-Fi Wireframe → Hi-Fi Design System → Dev Handover[cite: 2]
  1. User Requirements: ပစ်မှတ်ထားသော အသုံးပြုသူများ၊ ၎င်းတို့၏ အခက်အခဲများ (pain points)၊ အဓိက စီးပွားရေးလုပ်ငန်းဆောင်တာများနှင့် နည်းပညာပိုင်းဆိုင်ရာ ကန့်သတ်ချက်များကို သတ်မှတ်ခြင်း။[cite: 2]
  2. User Flow Diagramming: အမြင်ပိုင်းဆိုင်ရာ ဒီဇိုင်းများ မဆွဲမီ ယုတ္တိကျသော သွားလာမှု လမ်းကြောင်းများ၊ အသုံးပြုသူ၏ ဆုံးဖြတ်ချက်ချရမည့် နေရာများနှင့် မျက်နှာပြင်ပြောင်းလဲမှုများကို ပုံဖော်ရေးဆွဲခြင်း။[cite: 2]
  3. Low-Fidelity (Lo-Fi) Wireframing: အမြင်အာရုံ အနှောင့်အယှက်များ မပါဝင်ဘဲ သတင်းအချက်အလက် တည်ဆောက်ပုံကို အတည်ပြုရန် အဖြူအမည်း (grayscale) အကြမ်းဖျင်း တည်ဆောက်ပုံများကို ရေးဆွဲခြင်း။[cite: 2]
  4. High-Fidelity (Hi-Fi) Design: Auto-layout၊ design tokens၊ responsive breakpoints များနှင့် အခြေအနေပြောင်းလဲမှုများ (interactive state variants) ကို အသုံးပြု၍ Figma တွင် လက်တွေ့ထုတ်လုပ်ရန် အသင့်ဖြစ်သော အချောသတ် မျက်နှာပြင်များကို တည်ဆောက်ခြင်း။[cite: 2]
  5. Dev Handover & Documentation: အမြင်ပိုင်းဆိုင်ရာ ဒီဇိုင်းများကို software engineer များအတွက် လက်တွေ့လုပ်ဆောင်နိုင်သော သတ်မှတ်ချက်များ၊ tokens များနှင့် asset pipelines များအဖြစ်သို့ ပြောင်းလဲပေးခြင်း။[cite: 2]

၂။ SDLC နှင့် Sequence Diagram ချိတ်ဆက်မှု (SDLC & Sequence Diagram Alignment)[cite: 2]

User Requirements မှ UI State Flows သို့ ပြောင်းလဲရာတွင် UI/UX designer များအနေဖြင့် မျက်နှာပြင် အခြေအနေ (screen states) များကို နည်းပညာပိုင်းဆိုင်ရာ sequence diagram များနှင့် တိုက်ရိုက် ချိတ်ဆက်စဉ်းစားရပါမည်-[cite: 2]

[User Action] ──► (Frontend UI) ──► [API Request] ──► (Backend Engine) ──► [DB Query]
                                                                                │
[Render State] ◄── (Update UI) ◄── [JSON Response] ◄────────────────────────────┘

API Sequence နှင့် UI States နှိုင်းယှဉ်ချက် (Mapping Matrix)[cite: 2]

  • Request Trigger: ခလုတ်များ၊ ဖောင်တင်ခြင်းများ၊ လက်ဟန်အမူအရာများ (onClick, onSubmit)။[cite: 2]
  • In-Flight State: Skeleton Loaders များ၊ လုပ်ဆောင်နေကြောင်းပြသသည့် အရာများ၊ ယာယီပိတ်ထားသော ခလုတ်များ (isLoading: true)။[cite: 2]
  • Success State: အသိပေးစာများ (Toast Notifications)၊ မျက်နှာပြင် ကူးပြောင်းခြင်းများ၊ ဒေတာများကို ပြသခြင်း (status: 200)။[cite: 2]
  • Failure / Edge Case: Error ပြသသည့် Box များ၊ စာသားနှင့်တွဲလျက်ပါသော အမှားပြစာများ၊ ပြန်လည်ကြိုးစားရန် ခလုတ်များ (status: 4xx / 5xx)။[cite: 2]

၃။ User Flow ရေးဆွဲခြင်း စံသတ်မှတ်ချက်များ (User Flow Standard Specifications)[cite: 2]

User flow diagram များသည် layout ပုံကြမ်းများ မရေးဆွဲမီ ဆော့ဖ်ဝဲ၏ တည်ဆောက်ပုံကို ပုံဖော်ပေးပါသည်။[cite: 2]

Flowchart သင်္ကေတများနှင့် အဓိပ္ပာယ်သတ်မှတ်ချက်များ[cite: 2]

  • ဘဲဥပုံ / အဝိုင်း (Start / End): အက်ပ် စတင်သည့်နေရာ (ဥပမာ - Launch App) သို့မဟုတ် ပြီးဆုံးသည့် အခြေအနေ (ဥပမာ - Order Completed) ကို ညွှန်ပြသည်။[cite: 2]
  • ထောင့်မှန်စတုဂံ (Screen / Page): သီးခြား UI မျက်နှာပြင်တစ်ခု (ဥပမာ - Item Detail Screen, Checkout Page) ကို ကိုယ်စားပြုသည်။[cite: 2]
  • စိန်ပုံစံ (Decision Point): ယုတ္တိပိုင်းဆိုင်ရာ လမ်းခွဲမှု သို့မဟုတ် အခြေအနေ စစ်ဆေးမှုများ (ဥပမာ - Is User Authenticated? → Yes / No) ကို အကဲဖြတ်သည်။[cite: 2]
  • အနားပြိုင်စတုဂံ (Data Input / Output): အသုံးပြုသူ ထည့်သွင်းရမည့် အချက်အလက်များ သို့မဟုတ် ဒေတာများ (ဥပမာ - Enter Payment Slip, OTP Input) ကို ညွှန်ပြသည်။[cite: 2]
  • မြား (User Action / Direction): အသုံးပြုသူ၏ လုပ်ဆောင်ချက်များ၊ လက်ဟန်များ သို့မဟုတ် အလိုအလျောက် မျက်နှာပြင် ကူးပြောင်းမှုများကို ညွှန်ပြသည်။[cite: 2]

၄။ ဒီဇိုင်းစနစ် တည်ဆောက်ပုံနှင့် Variables များ (Design System Architecture & Variables)[cite: 2]

Developer များအတွက် အဆင်ပြေစေမည့် Figma တည်ဆောက်ပုံဖြစ်စေရန် Design Variable များသည် CSS Custom Properties, Tailwind CSS config, သို့မဟုတ် mobile UI framework များနှင့် တိုက်ရိုက်ချိတ်ဆက်နိုင်သော Two-Tier Token System (အလွှာနှစ်ခုပါသော Token စနစ်) အတိုင်း သတ်မှတ်ရပါမည်။[cite: 2]

[ Primitive Value ] → [ Semantic Design Token ] → [ UI Component Usage ][cite: 2]

Variable အမည်ပေးခြင်း စံနှုန်းများ[cite: 2]

၁. Color Tokens[cite: 2]

  • Primitives (Base Scale): blue/100, blue/500, slate/900[cite: 2]
  • Semantic Tokens:[cite: 2]
    • color/brand/primary → blue/500 သို့ ချိတ်ဆက်သည်။[cite: 2]
    • color/text/primary → slate/900 သို့ ချိတ်ဆက်သည်။[cite: 2]
    • color/bg/surface → white သို့ ချိတ်ဆက်သည်။[cite: 2]
    • color/border/default → slate/200 သို့ ချိတ်ဆက်သည်။[cite: 2]

၂. Spacing Tokens (8-Point System)[cite: 2]

Token Name Value (px) Rem Equivalent CSS Output Mapping

spacing/sm 8px 0.5rem var(--spacing-sm)
spacing/md 16px 1.0rem var(--spacing-md)
spacing/lg 24px 1.5rem var(--spacing-lg)
spacing/xl 32px 2.0rem var(--spacing-xl)

၆။ Developer ထံ လွှဲပြောင်းခြင်းဆိုင်ရာ စံနှုန်းများ (Developer Handover Protocol & Specs)[cite: 2]

  • Variables & Tokens: အရောင်များ၊ ကွာဟချက်များ (gaps)၊ padding နှင့် ဖောင့်စတိုင်များ အားလုံးကို global variables များနှင့် ချိတ်ဆက်ထားရမည်။[cite: 2]
  • Auto-Layout Verification: စာသားများ သို့မဟုတ် responsive card များတွင် ပုံသေ အရွယ်အစား (fixed-frame dimensions) များ မရှိစေရပါ။[cite: 2]
  • Component Variants: UI အစိတ်အပိုင်းများတွင် အခြေအနေ အပြောင်းအလဲများ (Default, Hover, Pressed, Disabled, Focus) ပါဝင်ရမည်။[cite: 2]
  • Asset Exporting: Icon များအားလုံးကို vector SVGs (Fill: CurrentColor) အဖြစ် သတ်မှတ်ထားပြီး ပုံများကို export ထုတ်နိုင်သော PNG/WebP အဖြစ် သတ်မှတ်ထားရမည်။[cite: 2]
  • Edge Cases Covered: ဒေတာမရှိချိန် (Empty Data)၊ အင်တာနက်မရချိန် (Network Error) နှင့် ဒေတာဆွဲယူနေချိန် (Loading Skeleton) များအတွက် မျက်နှာပြင်များကို အတိအလင်း ရေးဆွဲထားရမည်။[cite: 2]
  • Annotations Added: လုပ်ဆောင်ချက်ဆိုင်ရာ စည်းမျဉ်းများ (ဥပမာ - regex စစ်ဆေးမှုများ၊ ငွေကြေးပြသမှု ပုံစံများ၊ API လိုအပ်ချက်များ) ကို ရှင်းလင်းချက် မှတ်စုများ (sticky notes) ဖြင့် မှတ်တမ်းတင်ထားရမည်။[cite: 2]

ရှင်းလင်းချက် နမူနာကုဒ် (Sample Developer Annotation Code)[cite: 2]

/* Component: Primary Action Card */
.card-container {
  display: flex;
  flex-direction: column;
  padding: var(--spacing-md);       /* 16px */
  gap: var(--spacing-sm);           /* 8px */
  background-color: var(--color-bg-surface);
  border-radius: var(--radius-md);  /* 8px */
  border: 1px solid var(--color-border-default);
}

.card-title {
  color: var(--color-text-primary);
  font-size: var(--font-size-lg);  /* 18px */
  font-weight: 600;
}
```
