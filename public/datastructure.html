Data Structures & Big Data Architecture

Comprehensive guide on Structured, Semi-structured, Unstructured Data, Relationships, Normalization, and Big Data Architecture.

Structured Data & Relationship Design (ဖွဲ့စည်းပုံကျသော ဒေတာနှင့် ဆက်နွှယ်မှုများ)

Column တွေ၊ Row တွေနဲ့ တိကျတဲ့ Data Model (Schema) တည်ဆောက်ပုံရှိသော Relational Databases (MySQL, PostgreSQL) များအတွက် ဒီဇိုင်းဆွဲရာတွင် အဓိက လေ့လာရမည့် အပိုင်းများ -

1. Relationships Types (ဆက်နွှယ်မှုပုံစံများ)

👤 🪪
One-to-One (1:1)

အရာဝတ္ထုတစ်ခုသည် အခြားအရာဝတ္ထုတစ်ခုနှင့်သာ တိုက်ရိုက်သက်ဆိုင်ခြင်း။
ဥပမာ - User တစ်ဦးလျှင် User Profile တစ်ခုသာရှိခြင်း။

👤 📦📦
One-to-Many (1:M)

အရာဝတ္ထုတစ်ခုသည် အခြားအရာဝတ္ထု အများအပြားနှင့် ချိတ်ဆက်နိုင်ခြင်း။
ဥပမာ - User တစ်ဦးက Order များစွာ တင်နိုင်ခြင်း (Foreign Key သုံးသည်)။

🛒 🛍️
Many-to-Many (M:N)

အရာဝတ္ထုအများအပြားသည် အပြန်အလှန် အများအပြားနှင့် ချိတ်ဆက်ခြင်း။
ဥပမာ - Order တစ်ခုတွင် Product အများကြီးပါနိုင်ပြီး Product တစ်ခုလည်း Order များစွာတွင် ပါနိုင်ခြင်း (Pivot Table လိုအပ်သည်)။

2. Normalization စဉ်းစားရမည့် အခြေအနေများ

Database ထဲတွင် Data တွေ ထပ်ခါထပ်ခါ မဖြစ်စေရန် (Redundancy မဖြစ်ရန်) နှင့် Data Integrity ကောင်းမွန်စေရန် Normalization လုပ်ဆောင်ရာတွင် အောက်ပါအချက်များကို စဉ်းစားရပါမည် -

  • 1NF (First Normal Form): Column တစ်ခုချင်းစီတွင် တန်ဖိုးတစ်ခုတည်း (Atomic Value) သာ ရှိရမည်။ ကော်မာခံပြီး ဒေတာများကို တစ်ကွက်ထဲ ပေါင်းမထည့်ရပါ။
  • 2NF (Second Normal Form): Composite Primary Key ရှိနေသည့်အခါ Non-key column တိုင်းသည် Primary Key အားလုံးအပေါ်တွင် အပြည့်အဝ မှီခိုနေရမည် (Partial Dependency ဖယ်ရှားခြင်း)။
  • 3NF (Third Normal Form): Primary Key မဟုတ်သော Column အချင်းချင်း မှီခိုနေခြင်း (Transitive Dependency) မရှိရပါ။ ဥပမာ - Product ID မှ Product Price ကို သိနိုင်ပါက Order Table ထဲတွင် Price ကို ထပ်မထည့်ဘဲ Product Table တွင်သာ ထားရမည်။
  • Performance vs Normalization (Denormalization): 3NF အထိ တင်းကျပ်စွာ ခွဲထုတ်ထားပါက Join များလွန်း၍ Read Speed နှေးတတ်ရာ Read-heavy အခြေအနေများတွင် တမင်တကာ Data ပေါင်းသိမ်းရန် (Denormalization) ကိုလည်းချိန်ဆ စဉ်းစားရသည်။

Semi-Structured Data (တစ်စိတ်တစ်ပိုင်း ဖွဲ့စည်းပုံကျသော ဒေတာ)

တင်းကျပ်တဲ့ Table Schema မရှိပေမယ့် Key-Value pairs တွေ၊ Hierarchy (အထက်အောက် အဆင့်ဆင့်) တွေနဲ့ ဖွဲ့စည်းထားတဲ့ ဒေတာဖြစ်ပါတယ်။

  • Characteristics: JSON, XML နဲ့ NoSQL (MongoDB) Collection တွေမှာ အသုံးများသည်။ Field အသစ်တွေ အလွယ်တကူ ထပ်တိုးလို့ရသည်။
  • Design Core: Document Modeling (Embedding vs Referencing) နဲ့ Indexing Strategies တွေကို အသုံးပြုရသည်။
{
  "userId": 1,
  "name": "Mg Mg",
  "preferences": {
    "theme": "dark",
    "notifications": true
  }
}

Unstructured Data (ဖွဲ့စည်းပုံမကျသော ဒေတာ)

ကြိုတင်သတ်မှတ်ထားတဲ့ Schema သို့မဟုတ် Data Model လုံးဝမရှိဘဲ သဘာဝအတိုင်း တည်ရှိနေတဲ့ ဒေတာအမျိုးအစား ဖြစ်ပါတယ်။

  • Characteristics: Text files, PDF, Audio, Video နဲ့ DICOM Medical Image တွေ ပါဝင်ပါတယ်။ စုစုပေါင်း Enterprise Data ၏ ၈၀% ကျော်ရှိသည်။
  • Design Core: Object Storage (Cloudflare R2, AWS S3) တွေမှာ တိုက်ရိုက်သိမ်းဆည်းပြီး Metadata တွေကို Structured Database မှာ Index ပြန်လုပ်ရပါတယ်။
Storage Strategy: ဖိုင်များကို Object Storage တွင် သိမ်းပြီး Database တွင် URL သို့မဟုတ် File Path ကိုသာ သိမ်းဆည်းခြင်း။

Array & Object Array (အေအေးနှင့် အော့ဘ်ဂျက်အေအေး)

Programming နဲ့ Semi-structured data တွေမှာ အချက်အလက်အမြောက်အမြားကို စုစည်းသိမ်းဆည်းဖို့ အသုံးအများဆုံး structure တွေ ဖြစ်ပါတယ်။

1. Simple Array ဥပမာ (String/Number Array):

const roles = ["Admin", "Editor", "Viewer"];

2. Object Array ဥပမာ (Complex Data Structure):

[
  {
    "productId": 101,
    "name": "Laptop",
    "price": 1500000,
    "tags": ["electronics", "computers"]
  },
  {
    "productId": 102,
    "name": "Mouse",
    "price": 25000,
    "tags": ["accessories", "wireless"]
  }
]

From Data Types to Big Data (ဘယ်လို Big Data ဖြစ်လာသလဲ)

အထက်ပါ Structured၊ Semi-structured နဲ့ Unstructured ဒေတာတွေဟာ သာမန် Single Database တွေမှာ မဆံ့တော့လောက်အောင် Volume (ပမာဏကြီးမားခြင်း)၊ Velocity (မြန်ဆန်စွာ ဝင်ရောက်လာခြင်း) နဲ့ Variety (အမျိုးအစားစုံလင်ခြင်း) ဆိုတဲ့ 3Vs လက္ခဏာတွေနဲ့ ပြည့်လာတဲ့အခါ Big Data အဖြစ်သို့ ကူးပြောင်းသွားပါတယ်။

Data Type How it transforms to Big Data?
Structured Data သန်းပေါင်းများစွာသော User Transactions တွေနေ့စဉ်ဝင်လာတဲ့အခါ (Distributed Databases - Cassandra, PostgreSQL Sharding) လိုအပ်လာပါတယ်။
Semi-Structured IoT Sensors တွေနဲ့ Web Logs တွေကနေ JSON/Log stream တွေ တစ်စက္ကန့်ကို ယူနစ်သန်းချီဝင်လာခြင်း (Kafka, MongoDB Clusters)။
Unstructured ဗီဒီယိုဖိုင်များ၊ မြို့ပြ CCTV ရုပ်သံများနှင့် ဆေးဘက်ဆိုင်ရာ DICOM Imaging ဖိုင်များ Petabytes ပမာဏအထိ စုပုံလာခြင်း (Data Lakes)။

What's Next? (ဘာတွေ ဆက်လုပ်လို့ရလဲ)

Big Data အဆင့်ကို ရောက်ရှိသွားတဲ့အခါ အောက်ပါ Modern Architecture တွေနဲ့ AI Workflow တွေကို ဆက်လက်တည်ဆောက်နိုင်ပါတယ် -

  • Data Pipelines (ETL / ELT): Apache Airflow, n8n သို့မဟုတ် Kafka ကိုသုံးပြီး Data တွေကို Extract လုပ်၊ Transform လုပ်ကာ Data Warehouse တွေဆီ ပို့ဆောင်ခြင်း။
  • Data Lakehouse Architecture: Structured နဲ့ Unstructured ဒေတာတွေကို တစ်နေရာတည်းမှာ ပေါင်းစပ်သိမ်းဆည်းပေးတဲ့ Delta Lake / Apache Iceberg နည်းပညာများ အသုံးပြုခြင်း။
  • Vector Embeddings & RAG Systems: Unstructured text တွေကို Vectorize လုပ်ပြီး Cloudflare Vectorize သို့မဟုတ် Pinecone ထဲသိမ်းကာ AI Chatbot တွေနဲ့ ချိတ်ဆက်ခြင်း။
  • Business Intelligence (BI): Metabase သို့မဟုတ် Apache Superset တို့ကို အသုံးပြုပြီး Dashboard တွေပေါ်တင်ကာ Data Analytics ထုတ်ခြင်း။
